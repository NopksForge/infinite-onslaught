# Infinite Onslaught — CLAUDE.md

Roguelite tower-defense game with AI-powered crafting. Combines items via Ollama LLM, persists discoveries in SQLite, runs as a single desktop executable via Wails.

---

## Stack

| Layer | Technology |
|-------|-----------|
| Desktop shell | Wails v2 (embeds frontend into Go binary) |
| Backend | Go 1.22, `net/http` for localhost API (no framework) |
| Database | SQLite via `modernc.org/sqlite` (pure Go, no CGO) |
| LLM | Ollama local API (`llama3.1:8b` by default) |
| Frontend | React 19 + Vite 6 + Tailwind CSS v4 |

## Running

### Full Wails (recommended when you have a display)

```bash
wails dev
```

Open the proxy URL `wails dev` prints (often `http://localhost:34115`). The bridge `window['go']` is only available there.

### Backend + frontend without Wails (e.g. WSL2 headless)

Use **one** of the following.

**Makefile (repo root):**

```bash
make backend          # go run . -serve  → API on :8081 (foreground)
make frontend         # cd frontend && npm run dev
make dev              # both in one terminal (bash: API in background, then Vite; Ctrl+C stops Go)
```

**Manual (two terminals):**

```bash
# Terminal 1: HTTP API only (no Wails window)
go run . -serve
# or: go run . serve

# Terminal 2:
cd frontend && npm run dev
```

The app must be launched as **`go run .`** (full `main` package), not `go run main.go` alone.

**Dual transport:** bridge when available; otherwise the frontend calls `http://localhost:8081/api/*`. The Go app always starts that HTTP server from `app.startup()` via `backend.StartAPIServer`.

### Ollama helpers (Makefile)

| Target | Purpose |
|--------|---------|
| `make ollama-kill` | Stop Ollama service / free port **11434** (OS-specific) |
| `make ollama-fresh` | `ollama-kill`, then `ollama serve` (foreground) |
| `make ollama-fresh-windows-ps` | Windows: PowerShell kill instead of netstat |

### Build (Windows `.exe`)

```bash
wails build
# Output: build/bin/infinite-onslaught.exe
```

Linux/WSL needs GTK/WebKit dev packages for `wails build`. Cross-compiling to `.exe` from Linux usually needs a Windows CGO toolchain; building on Windows is simplest.

## Go bound methods (`app.go`)

Callable from TypeScript via `window['go']['main']['App'].*`. Wails maps types from packages `infiniteonslaught/backend` and `infiniteonslaught/backend/craft` into `frontend/wailsjs/go/models.ts` as **`backend.*`** and **`craft.*`**.

| Method | Returns | Notes |
|--------|---------|-------|
| `GetResources()` | `[]craft.Item` | Four starter items |
| `Craft(item1, item2 string)` | `*backend.CraftResult, error` | Cache → LLM → persist |
| `ClearCraft()` | `error` | Clears items + combinations tables |
| `CheckOllama()` | `backend.OllamaStatus` | Pings Ollama `/api/tags` |

---

## HTTP server (`backend/server.go`, port 8081)

Mirrors the bridge for the HTTP fallback. Started by `backend.StartAPIServer(app)` from `App.startup()`.

| Method | Endpoint | Response |
|--------|----------|----------|
| GET | `/api/resources` | `[]craft.Item` |
| GET | `/api/ollama-status` | `OllamaStatus` |
| POST | `/api/craft` | `CraftResult` JSON body: `{"item1":"...", "item2":"..."}` |
| DELETE | `/api/craft` | 204 No Content |

Responses use `Content-Type: application/json`. CORS is `*` (localhost only). Request logging at DEBUG; errors at ERROR with context.

---

## Frontend transport (`craftApi.ts`, `StartPage.tsx`)

**Bridge-first, HTTP fallback:**

1. If `window['go']['main']['App']` exists → use it.
2. Else → `fetch` `http://localhost:8081/api/*`.

No Vite proxy: the browser talks to `:8081` directly when the bridge is missing.

## Database (SQLite)

Path: `game.db` (created next to the working directory on first run).

```sql
items        (name PK, description, emoji, created_from JSON)
combinations (key PK, result_name)   -- key = "itemA:itemB" sorted lexicographically
```

`created_from` is JSON: `[["Fire","Water"],["Steam","Ice"]]`.

## LLM config

Set in `app.go` `startup()` when constructing `craft.LLMClient`:

- Endpoint: `http://localhost:11434`
- Model: `llama3.1:8b`
- Timeout: 30 s

## Key decisions

- **No CGO for SQLite**: `modernc.org/sqlite` avoids CGO for the DB layer.
- **`backend/` layout**: Crafting + SQLite + LLM live under `backend/craft`; the localhost API and DTOs (`OllamaStatus`, `CraftResult`) live in package `backend`. The Wails `App` in `app.go` imports both and satisfies `backend.AppAPI` for `StartAPIServer`.
- **Bridge-first, HTTP fallback**: Same behavior in Wails, built app, raw Vite, or `go run . -serve`.
- **No Vite proxy**: Frontend hits `localhost:8081` or the bridge.
- **Ollama from Go**: Avoids browser CORS to Ollama; `CheckOllama` and HTTP `/api/ollama-status` use the Go client.
- **`assets_dev.go`**: Empty `assets` with `-tags dev`; production embeds `frontend/dist`.
- **No referenceId**: Single-user desktop; no per-session Redis IDs.
- **Discovery panel**: SQLite is authoritative; `sessionStorage` is only an in-session UI cache for discoveries.
