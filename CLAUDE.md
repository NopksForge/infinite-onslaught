# Infinite Onslaught — CLAUDE.md

Roguelite tower-defense game with AI-powered crafting. Combines items via Ollama LLM, persists discoveries in SQLite, runs as a single desktop executable via Wails.

---

## Stack

| Layer | Technology |
|-------|-----------|
| Desktop shell | Wails v2 (embeds frontend into Go binary) |
| Backend | Go 1.21, no HTTP framework for the main app |
| Database | SQLite via `modernc.org/sqlite` (pure Go, no CGO) |
| LLM | Ollama local API (`llama3.1:8b` by default) |
| Frontend | React 19 + Vite 6 + Tailwind CSS v4 |

## Running

### Development
```bash
# From repo root — starts Go + Vite dev server + opens Wails window
wails dev
```

Open the proxy URL that `wails dev` prints (usually `http://localhost:34115`). The Wails bridge (`window['go']`) is only available through that URL.

**Dual transport strategy:**
- **Bridge available** (proxy URL / built app) → all calls use `window['go']['main']['App'].*`
- **Bridge unavailable** (fallback) → `craftApi.ts` and `StartPage.tsx` fall back to HTTP calls to `http://localhost:8081/api/*`

The app always starts the HTTP server on `:8081` with CORS headers, so it works both in Wails and as a standalone server.

### Alternative: Backend-only dev mode
If you prefer to run the backend and frontend separately (e.g., WSL2 without display):
```bash
# Terminal 1: Go backend only (no Wails window)
go run -tags "dev webkit2_41" . serve

# Terminal 2: Frontend dev server (optional, runs on :5173)
cd frontend && npm run dev
```

When using the backend-only mode, the frontend still falls back to `http://localhost:8081/api/*` for all calls.

### Build .exe (Windows)
```bash
# Run on Windows or a Windows GitHub Actions runner
wails build
# Output: build/bin/infinite-onslaught.exe
```

Cross-compiling from Linux/WSL2 to `.exe` requires CGO cross-compilation toolchain setup. Easiest path is building natively on Windows.

## Go bound methods (app.go)

These are callable from TypeScript via `window['go']['main']['App'].*`:

| Method | Returns | Notes |
|--------|---------|-------|
| `GetResources()` | `[]craft.Item` | Always returns the 4 starter items |
| `Craft(item1, item2 string)` | `*CraftResult, error` | DB cache → LLM → persist |
| `ClearCraft()` | `error` | Wipes items + combinations tables |
| `CheckOllama()` | `OllamaStatus` | Pings `/api/tags`; returns model name |

---

## HTTP server (server.go, port 8081)

Mirrors all Go bridge methods and adds Ollama status check. Used as fallback when the Wails bridge is unavailable.

| Method | Endpoint | Response |
|--------|----------|----------|
| GET | `/api/resources` | `[]Item` |
| GET | `/api/ollama-status` | `OllamaStatus` |
| POST | `/api/craft` | `CraftResult` (body: `{"item1":"...", "item2":"..."}`) |
| DELETE | `/api/craft` | 204 No Content |

All responses set `Content-Type: application/json`. CORS is open (`*`) since this only binds to localhost.

Logging: all requests logged at DEBUG level, errors logged at ERROR level with context (item names, error message).

---

## Frontend transport (craftApi.ts, StartPage.tsx)

Both components use **bridge-first, HTTP fallback**:

1. Check if `window['go']['main']['App']` is available (synchronous, no timeout)
2. If yes → use Wails bridge calls directly
3. If no → fetch from `http://localhost:8081/api/*`

**No Vite proxy is used.** The HTTP fallback talks directly to the Go backend on `:8081`.

This approach works in all environments:
- **Wails proxy URL** → bridge available, HTTP not needed
- **Built app** → bridge available, HTTP not needed
- **Raw Vite dev server** (fallback) → bridge unavailable, falls back to HTTP
- **Headless backend** (`go run . serve`) → bridge unavailable, falls back to HTTP

## Database (SQLite)

File: `game.db` (created next to the binary on first run).

```sql
items        (name PK, description, emoji, created_from JSON)
combinations (key PK, result_name)   -- key = "itemA:itemB" sorted
```

`created_from` is a JSON array of arrays: `[["Fire","Water"],["Steam","Ice"]]`.

## LLM config

Hardcoded in `app.go` `startup()`:
- Endpoint: `http://localhost:11434`
- Model: `llama3.1:8b`
- Timeout: 30 s

To change model or endpoint, edit those two lines in `app.go`.

## Key decisions

- **No CGO for SQLite**: `modernc.org/sqlite` is a pure-Go SQLite port — no CGO needed for the DB layer.
- **Bridge-first, HTTP fallback**: Frontend tries Wails bridge (`window['go']`) first (fastest, no network). If unavailable, falls back to HTTP on `:8081`. Works in all dev scenarios (Wails proxy, Vite dev, headless backend).
- **No Vite proxy**: Removed proxy config that added complexity. Frontend calls directly to `localhost:8081/api` or uses bridge. Both work in dev and prod.
- **Ollama check via Go**: `StartPage` no longer fetches Ollama directly (browser CORS issues). Instead calls `CheckOllama()` via bridge or `GET /api/ollama-status` via HTTP — Go handles it server-side, no CORS.
- **`assets_dev.go`**: Provides empty `assets` in dev mode so Go compiles with `-tags dev`. Production uses `assets.go` with embedded frontend/dist.
- **No referenceId**: Old HTTP server used per-session IDs for Redis isolation. Desktop app is single-user; removed entirely.
- **Discovery list in sessionStorage**: The SQLite DB is the source of truth for combinations. `sessionStorage` is only the in-session UI cache for the Discovery panel.
- **`backend/` directory**: Legacy Gin+Redis server from before the Wails migration. Unused — can be deleted.
