# Infinite Onslaught — CLAUDE.md

Roguelite tower-defense game with AI-powered crafting. Combines items via Ollama LLM, persists discoveries in SQLite, runs as a single desktop executable via Wails.

**Core loop:** Craft new items → drag them into the Arena as defenders → kill waves of monsters → earn XP → level up → craft stronger things → survive longer.

---

## Stack

| Layer | Technology |
|-------|-----------|
| Desktop shell | Wails v2 (embeds frontend into Go binary) |
| Backend | Go 1.22, `net/http` for localhost API (no framework) |
| Database | SQLite via `modernc.org/sqlite` (pure Go, no CGO) |
| LLM | Ollama local API (`llama3.1:8b` by default) |
| Frontend | React 19 + Vite 6 + Tailwind CSS v4 |

## Running

### Full Wails (recommended when you have a display)

```bash
wails dev
```

Open the proxy URL `wails dev` prints (often `http://localhost:34115`). The bridge `window['go']` is only available there.

### Backend + frontend without Wails (e.g. WSL2 headless)

**Makefile (repo root):**

```bash
make backend          # go run . -serve  → API on :8081 (foreground)
make frontend         # cd frontend && npm run dev
make dev              # both in one terminal (bash: API in background, then Vite; Ctrl+C stops Go)
```

**Manual (two terminals):**

```bash
# Terminal 1
go run . -serve

# Terminal 2
cd frontend && npm run dev
```

The app must be launched as **`go run .`** (full `main` package), not `go run main.go` alone.

**Dual transport:** bridge when available; otherwise the frontend calls `http://localhost:8081/api/*`. The Go app always starts that HTTP server from `app.startup()` via `backend.StartAPIServer`.

### Ollama helpers (Makefile)

| Target | Purpose |
|--------|---------|
| `make ollama-kill` | Stop Ollama service / free port **11434** |
| `make ollama-fresh` | `ollama-kill`, then `ollama serve` (foreground) |
| `make ollama-fresh-windows-ps` | Windows: PowerShell kill instead of netstat |

### Build (Windows `.exe`)

```bash
wails build
# Output: build/bin/infinite-onslaught.exe
```

Linux/WSL needs GTK/WebKit dev packages for `wails build`. Building on Windows is simplest.

## Go bound methods (`app.go`)

Callable from TypeScript via `window['go']['main']['App'].*`. Wails maps types from `infiniteonslaught/backend` and `infiniteonslaught/backend/craft` into `frontend/wailsjs/go/models.ts` as `backend.*` and `craft.*`.

| Method | Returns | Notes |
|--------|---------|-------|
| `GetResources()` | `[]craft.Item` | Four starter items (includes DefenderType + Stats) |
| `Craft(item1, item2 string)` | `*backend.CraftResult, error` | Cache → LLM → persist |
| `ClearCraft()` | `error` | Clears items + combinations tables |
| `CheckOllama()` | `backend.OllamaStatus` | Pings Ollama `/api/tags` |

## HTTP server (`backend/server.go`, port 8081)

Mirrors the bridge for the HTTP fallback. Started by `backend.StartAPIServer(app)` from `App.startup()`.

| Method | Endpoint | Response |
|--------|----------|----------|
| GET | `/api/resources` | `[]craft.Item` |
| GET | `/api/ollama-status` | `OllamaStatus` |
| POST | `/api/craft` | `CraftResult` — body: `{"item1":"...", "item2":"..."}` |
| DELETE | `/api/craft` | 204 No Content |

CORS is `*` (localhost only).

## Frontend transport (`craftApi.ts`)

**Bridge-first, HTTP fallback:**

1. If `window['go']['main']['App']` exists → use Wails bridge.
2. Else → `fetch` `http://localhost:8081/api/*`.

No Vite proxy. The browser talks to `:8081` directly when the bridge is absent.

## Database (SQLite)

Path: `game.db` (created next to the working directory on first run).

```sql
items        (name PK, description, emoji, created_from JSON,
              defender_type TEXT, stats TEXT)   -- stats is JSON object
combinations (key PK, result_name)             -- key = "itemA:itemB" sorted
```

`created_from` JSON: `[["Fire","Water"],["Steam","Ice"]]`.
`stats` JSON: `{"speed_mult":1.5,"damage_mult":2.0,"duration_mult":1.0,"range_mult":0.8,"area_mult":1.2}`.

Schema is additive — new columns are added via `ALTER TABLE IF` so existing `game.db` files upgrade automatically.

## Defender system

Each crafted `Item` carries a `DefenderType` and `DefenderStats` generated by the LLM (and persisted in the DB). The four types:

| Type | Behaviour |
|------|-----------|
| `alive_melee` | Chases nearest monster; attacks in melee range; expires after lifetime |
| `alive_range` | Stationary; shoots nearest monster within range; expires after lifetime |
| `spell` | One-shot AOE on placement; deals damage to all monsters within radius |
| `obstacle` | Stationary wall; damages monsters in contact per tick; erodes under attack |

`DefenderStats` multipliers (0.5–3.0, set by LLM, validated/clamped in `sanitise()`):

```
speed_mult    – move speed
damage_mult   – attack / spell damage
duration_mult – HP and lifetime
range_mult    – attack / projectile range
area_mult     – spell / obstacle contact area
```

Base stats per type live in `gameContext.tsx` (`BASE_DEFENDER`). Final stat = base × multiplier.

## Game loop (`frontend/src/game/gameContext.tsx`)

`GameProvider` wraps `GamePage`. The `useGame()` hook exposes game state and actions to any child component.

**State shape (`GameState`):**

```ts
status: 'idle' | 'active' | 'game_over'
wave: number          // last wave spawned (0 before first)
xp: number
level: number         // derived each tick: largest n where xpForLevel(n) <= xp
baseHp: number        // player base HP (100 max)
defenders: Defender[]
monsters: Monster[]
waveTimer: number     // seconds until next wave spawns
spawnTimer: number    // seconds until next monster from spawnQueue appears
spawnQueue: MonsterTemplate[]
```

**Wave system:**
- First wave spawns 12 s after game start; subsequent waves every 25 s.
- Monster count per wave: `2 + wave`. Templates cycle Goblin → Orc → Troll → Dragon every 2 waves.
- Each wave, monster HP/damage scale by `1.1^(wave-1)`; speed scales by `1.03^(wave-1)`.
- Individual monsters from the queue spawn 1.5 s apart.

**XP / leveling:**

```
xpForLevel(n) = (n-1) * n * 60
Level 1:  0 XP   Level 2: 60 XP   Level 3: 240 XP   Level 4: 540 XP …
```

**Game loop tick (RAF at 60 fps, dt capped at 100 ms):**
1. Decrement wave timer → populate spawn queue on expiry.
2. Decrement spawn timer → move next monster from queue into arena.
3. Move all monsters downward (toward base at y = 88 %).
4. Process defenders: melee chases + attacks; range shoots in radius; spell AOEs on first tick; obstacle damages adjacent monsters.
5. Monsters at y ≥ 88 % deal damage to base HP and are removed.
6. Dead monsters award XP; level is recomputed.
7. Dead/expired defenders are removed.

**Context actions:**

| Action | Description |
|--------|-------------|
| `startGame()` | Set status `active`; loop was already running from mount |
| `resetGame()` | Full state reset back to initial; starts active immediately |
| `deployDefender(item, x, y)` | Build a `Defender` from `DeployableItem`, push to state |
| `removeFromCraft(id)` | Sets `lastDeployedId`; `CraftingPanel` watches and removes the item |

## Crafting ↔ Arena drag-and-drop

All inter-panel drag uses **HTML5 DnD** (no pointer-event capture on cards, which conflicts).

**MIME types set on `dragStart`:**

| MIME type | Carries | Used by |
|-----------|---------|---------|
| `application/crafting-item` | Item UUID | Canvas `onDrop` (move), other items' `onDrop` (combine) |
| `application/defender-json` | Full item payload + `craftingId` | Arena `onDrop` (deploy) |
| `application/json` | Resource data | Canvas `onDrop` (place resource from panel) |

**Interactions:**

- **Drag item onto another item** → combine (craft). Each item card handles `onDragOver` / `onDrop`, stops propagation so the canvas doesn't also fire.
- **Drag item onto empty canvas space** → move to drop position.
- **Drag item onto Arena** → deploy as defender; `craftingId` in payload triggers `removeFromCraft` → item disappears from crafting table.
- **Click resource in ResourcePanel** → place randomly in crafting area middle.
- **Drag resource onto crafting canvas** → place at drop position.

## Key decisions

- **No CGO for SQLite**: `modernc.org/sqlite` — pure Go, no C toolchain needed.
- **`backend/` layout**: Crafting + SQLite + LLM under `backend/craft`; DTOs (`OllamaStatus`, `CraftResult`) in package `backend`. `App` in `app.go` satisfies `backend.AppAPI`.
- **Bridge-first, HTTP fallback**: Same behaviour in Wails, built app, raw Vite, or `go run . -serve`.
- **No Vite proxy**: Frontend hits `localhost:8081` or the Wails bridge directly.
- **Ollama from Go**: Avoids browser CORS to Ollama; all LLM calls go through Go.
- **`assets_dev.go`**: Empty `assets` with `-tags dev`; production embeds `frontend/dist`.
- **Single-user desktop**: No per-session IDs; SQLite is authoritative; `sessionStorage` is only an in-session UI cache for the Discovery panel.
- **Game state is client-side only**: `GameProvider` holds all arena/combat state in memory; no persistence between sessions (roguelite — each run is fresh).
- **HTML5 DnD for crafting cards**: Pointer-capture–based dragging conflicts with `draggable` elements (browser suppresses `pointermove` once DnD starts). All card interactions (move, combine, deploy) use HTML5 DnD exclusively.
